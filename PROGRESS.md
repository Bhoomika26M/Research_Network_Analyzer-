# Stage 1 progress — backend foundation

- Built: FastAPI + SQLAlchemy 2.0 (async) backend in `backend/` — 13 models (users, institutions, departments, researchers, publications, publication_authors, projects, project_members, conferences, conference_participations, citations, notifications, audit_logs) with UUID PKs, created_at/updated_at, soft deletes, enums, FK/unique/CHECK constraints and indexes.
- Schema: created on startup via `Base.metadata.create_all` in `app/main.py` (Alembic migrations come in a later stage; the `alembic/` scaffold is already in place).
- Infra: `backend/docker-compose.yml` starts postgres:16 + redis:7 only; run the API locally with `uvicorn app.main:app --reload`.
- Run: `cd backend && docker compose up -d && uvicorn app.main:app --reload` → health at http://localhost:8000/health, docs at /docs; env from `.env` (see `.env.example` — DATABASE_URL matches compose).
- Next: Stage 2 = auth, users, roles, audit logging (plus an Alembic migration replacing create_all).

# Stage 2 progress — auth, roles, audit logging

- Security: `app/core/security.py` does bcrypt hashing + JWT access (30 min) / refresh (7 days) tokens; `JWT_SECRET`, `JWT_ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES`, `REFRESH_TOKEN_EXPIRE_DAYS` are settings in `app/core/config.py` (override them in `.env`).
- Endpoints: `/api/v1/auth` register (default researcher, only system_admin may grant other roles), login (OAuth2 password form → access+refresh), refresh, me, change-password; `/api/v1/users` list with pagination+search, get one, PATCH role, activate/deactivate (system_admin only); `/api/v1/audit-logs` with category/user/date-range filters (system_admin only).
- Reusable deps in `app/api/deps.py`: `get_current_user`, `get_optional_user`, `require_roles("system_admin", ...)` — all four roles (researcher, institution_admin, reviewer, system_admin) enforced through the `user_role` enum; Redis fully removed from the app (lifespan, /health, deps, requirements) so nothing depends on it.
- Audit + errors: every login, failed login, registration, role change, password change (and activate/deactivate) writes an `audit_logs` row with user, action, IP address and category `security`/`user_activity`; all errors share one shape `{"error": {"code", "message", "status_code"}}` via `app/core/errors.py`; CORS still comes from `CORS_ORIGINS` in `.env`.
- Try it: `cd backend && uvicorn app.main:app --reload` → /docs → Authorize → register, login, GET /me, expect 403 on /users as a non-admin; create the first admin with `python scripts/create_admin.py`; deps added to requirements.txt (bcrypt, python-jose; redis dropped — no pip install was run here). Next: Stage 3.

# Stage 3 progress — institutions, departments, researchers, publications, files

- Routes: `/api/v1/institutions`, `/api/v1/departments`, `/api/v1/researchers`, `/api/v1/publications` (+ `/status` and `/file` sub-routes, 28 paths total); every list is paginated (generic `Page` envelope) with search/filters, and every error uses the shared `{"error": ...}` shape.
- Permissions: create/delete of institutions & departments and all of `/users` are system_admin-only; institution/dept update also allowed for the institution_admin managing that institution (resolved via their own researcher profile's department/affiliations — `users` table unchanged); researchers edit only their own profile, owners edit their own publications; status workflow draft → submitted → published → archived (+ submitted → draft) is enforced — owners submit/withdraw, reviewers & institution_admins publish/archive, invalid transitions get 409 and forbidden moves 403.
- Publications: co-authors with author_order + exactly one corresponding author, DOI format `10.xxxx/…` validated on create/update with case-insensitive duplicate check (409), title/year/type/status/researcher/institution/title-search filters, soft delete.
- Files: `POST/GET /api/v1/publications/{id}/file` — PDF/DOC/DOCX only, 20 MB cap, stored as a random uuid4 filename inside `UPLOAD_DIR` (settings, default `uploads/`, already in `.gitignore`); the original name/path is never trusted; audit rows cover institution/department/researcher/publication create-update-delete and every status change (`publication_history` / `user_activity`).
- New tables (picked up by create_all): `researcher_skills`, `research_interests`, `researcher_affiliations`; run `cd backend && pip install -r requirements.txt` first (adds python-multipart — the app will not boot without it), then `uvicorn app.main:app --reload` and walk /docs: institution → department → researcher → publication with co-authors → upload PDF → status flow → 403 on editing someone else's publication. Next: Stage 4.

# Stage 4 progress — collaboration, conferences, citations, dashboards, reports, search, notifications

- Part 1 (collaboration): `/api/v1/projects` (CRUD + status/institution/search filters + soft delete + `/mine` + member add/remove) and `/api/v1/institutional-collaborations` (CRUD); `GET /collaboration/co-authors/{researcher_id}` and `GET /collaboration/network` (+ `/graph` alias) build the graph with SQL GROUP BY aggregation (filters institution_id, year_from, year_to, limit), returning `{nodes, edges, links}`.

- Part 4 (dashboards/reports/search/notifications/audit): role-protected `/dashboard/researcher|institution|admin` (publications-per-year + by-type distributions), `/reports/{publications|research|collaboration|institutions}` (JSON + `?format=xlsx` via openpyxl + `?format=pdf` via reportlab, imported lazily), `/search?q=`, `/notifications` (+ read / read-all / unread-count); notifications fire on publication status change, project member add and conference registration; project/conference/citation/inst-collab writes are audited (`project_log` / `user_activity`).
- MissingGreenlet fix: every `Publication`/`Researcher`/`Project`/`Conference` response is rebuilt from an eager-loaded re-fetch (`selectinload` + `populate_existing`); `expire_on_commit=False` already set in `app/db/session.py`.

# Stage 10 — end-to-end verification against live Postgres + fixes

- 500s found and fixed: `GET /institutions`, `/researchers` and `/projects` all crashed because `InstitutionOut.model_validate()` / a schema field named after an ORM relationship (`departments`, `skills`, `interests`) trigger a lazy load of the relationship (MissingGreenlet); fixed with `Field(validation_alias=..., serialization_alias=...)` on the response schemas plus explicit Out construction in the routes. `GET /dashboard/researcher` still 500'd after that: the conferences query uses `populate_existing=True` with a nested `publication` load, which *unloads* `author_links` on the shared identity-map `Publication` instances, so the dashboard now materialises each collection into its DTO immediately after its own query.
- Route sweep: `backend/scripts/smoke_check.py` logs in as each seeded role and probes every parameterless GET from `/openapi.json` plus the role-protected endpoints and the 8 report exports — 41 routes + 10 role checks + 8 exports all pass (403/422 are expected, any 500 fails the run).
